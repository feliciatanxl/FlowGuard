# Client feedback traceability

The use cases in the first table were previously recorded as requests relayed by Ms. Vera. They are paraphrases, not quotations. Status is based on current FlowGuard code, tests, models/migrations, and the existing SecurePi integration review; unsupported requests are not presented as completed work.

## Recorded client use cases

| Client use case (paraphrased) | Status | Implementation response and evidence | Remaining limitation |
|---|---|---|---|
| Unattended item detection | Implemented PoC | Zone classes/thresholds, browser or SecurePi source, people/object proximity and elapsed time, `DetectionAlert`, linked `IncidentLog`, cooldown, source attribution, and lifecycle updates. | Depends on supported classes, camera geometry, thresholds, and PoC tracking; it is not a safety-certified detector. |
| Forgotten belongings at tables/seats | Partially supported | The unattended-object rule can flag a supported belonging after no nearby person remains. | It does not understand semantic table/seat ownership or reliably identify who placed the item. |
| Pick-up, set-down, or push-in recognition | Future work | Current services detect frames/objects and track configured unattended conditions. | No temporal action classifier or validated event-state model is called by FlowGuard. |
| Suspicious item or bomb detection | Future work | Generic object detection and unattended timing can start an operational review. | A generic model cannot identify or certify an explosive and must not create false safety assurance. |
| Restricted/empty-zone motion at night | Partially supported foundation | Zone CRUD and detection categories can represent restricted-zone monitoring. | There is no implemented schedule/after-hours calendar rule or validated low-light acceptance set. |
| Cats, dogs, or other animals | Future work | The packaged generic model may expose relevant classes, depending on the active model. | The integrated workflow/tests do not establish a configured or validated animal-alert requirement. |
| Rat/pest detection | Edge design; physical validation required | The documented external SecurePi design separates pest classes and has off-device confirmation/cooldown/event tests; FlowGuard can receive the resulting authenticated alert metadata. | The intended custom model/parser and physical Pi 5 + IMX500 rodent detection have not been validated and must not be demonstrated as a successful live detector. |
| Pest image, timestamp, and location | Partially supported infrastructure | Alerts can retain occurrence, zone/camera, source/device, and optional snapshot metadata; SecurePi variants can keep local evidence. | The fields do not become trustworthy pest evidence without a validated detector, and FlowGuard has no durable cloud image store. |
| Unique rat re-identification | Future research | No FlowGuard pest-identity embedding, dataset, or evaluation exists. | Individual animal re-identification is materially different from class detection and remains unverified. |
| Pest hotspot areas/shops | Future work | Zone and event timestamps could support later aggregation. | Hotspot analytics would be misleading until validated pest observations and stable location data exist. |
| Recognise the same known person again | Partially supported | Enrolled identity can be recognised at Gate Scanner/V-Patrol checkpoints; Node re-checks current PostgreSQL account state. | This is consented checkpoint recognition with proof-of-concept head-turn liveness, not continuous tracking or certified anti-spoofing. |
| Continuous cross-camera person re-identification | Future work | No multi-camera identity graph, track hand-off, or cross-camera re-identification model exists. | Checkpoint facial recognition must not be described as continuous person tracking. |

## Scope statement

FlowGuard is an academic proof of concept. Current evidence supports the implemented access, logistics, monitoring, incident, support, and deployment architecture. Temporal action recognition, explosive classification, production pest detection, pest re-identification/hotspots, and continuous cross-camera person re-identification remain future deployment or research work.
