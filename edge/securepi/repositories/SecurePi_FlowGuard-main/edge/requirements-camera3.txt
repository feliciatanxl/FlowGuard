# SecurePi — Raspberry Pi 4 + Camera Module 3 CPU-INFERENCE dependencies.
#
# This is for the DEVELOPMENT hardware path (edge/run_camera3.py): a normal Camera
# Module 3 frame captured with Picamera2, run through the six-class custom best.pt with
# Ultralytics on the Pi CPU. It is DELIBERATELY SEPARATE from requirements-pi.txt (the
# IMX500 runtime), which must stay lightweight and must NOT pull in PyTorch/Ultralytics.
# Install this ONLY on the Pi 4 dev unit doing CPU inference.
#
# -------------------------------------------------------------------------
# RECOMMENDED INSTALL — Raspberry Pi OS (Bookworm) 64-bit:
#
#   # System camera stack first (apt, not pip — matches libcamera/Qt):
#   sudo apt update
#   sudo apt install -y python3-picamera2 python3-opencv python3-venv
#
#   # A venv that can still see the apt-installed picamera2/opencv:
#   python3 -m venv --system-site-packages ~/securepi-venv
#   source ~/securepi-venv/bin/activate
#   pip install -r edge/requirements-camera3.txt
# -------------------------------------------------------------------------
#
# NOTE: on the Pi, install a CPU-only PyTorch wheel (Ultralytics pulls torch in). The
# generic PyPI 'torch' resolves to a CPU build on aarch64; if pip cannot find a wheel,
# use the piwheels index (default on Raspberry Pi OS) or a pinned CPU wheel.

ultralytics>=8.3        # YOLOv8 inference API (loads best.pt, runs predict)
# torch is a transitive dependency of ultralytics; pinned loosely here so a from-scratch
# venv resolves. Use a CPU build on the Pi (no CUDA on Raspberry Pi).
# torch>=2.2 ; platform_machine == "aarch64"

# picamera2 / opencv come from apt (system site packages) — NOT pinned here so pip never
# tries to build an incompatible camera stack. See the apt line above.
numpy>=1.21             # transitive with opencv/ultralytics; listed for a clean venv
